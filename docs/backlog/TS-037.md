## Acceptance Criteria

- [ ] Inventory connector, store, runtime, specialist, aggregator, validation, assessment, review and AI interfaces with versioned schemas and capability declarations.
- [ ] Define backward-reading, migration and unsupported-version behavior for observations, findings, snapshots, graph definitions and review decisions.
- [ ] Create reusable adapter conformance tests and independent component examples; keep cloud SDKs and SQL out of domain contracts.
- [ ] Define plugin discovery/configuration allowlists and compatibility/deprecation rules; do not execute untrusted downloaded plugins automatically.
- [ ] Define a versioned provider-neutral DAG/task specification for dependencies, identity gates, fan-out/join, Python and SQL stages, retries, timeouts and output references; reject cycles and unsupported native capabilities.
- [ ] Separate application services from transport so Streamlit can call authorized commands directly or through an optional API; do not require a separately deployed microservice for every reusable component.

## Verification

Run conforming and deliberately nonconforming adapters, old-snapshot replay, schema upgrade and unavailable-capability tests.

Record commands/results, decisions, deferred child issues and live versus fixture/replay boundaries.

- No unsupported legal verdicts or scores from incomplete identity/evidence/coverage.
