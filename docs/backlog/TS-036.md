## Acceptance Criteria

- [ ] Obtain maintainer approval for a code license and add LICENSE, notices and package metadata; distinguish code licensing from source-data rights.
- [ ] Publish contribution, conduct, governance and private vulnerability-reporting policies; identify maintainer and review responsibilities without inventing contacts or response promises.
- [ ] Define release versioning, support/deprecation policy, changelog and dependency update ownership; track SBOM/dependency/license checks with TS-029.
- [ ] Provide rights-safe examples and a documented first-contribution path; never redistribute raw personal data or licensed source datasets by default.
