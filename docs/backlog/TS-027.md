## Acceptance Criteria

- [ ] Reuse the agreed design and authorized application services for case/review commands; a separate HTTP API deployment is optional.
- [ ] Support intake, candidate confirmation, stages, comparison, citations, clarification and review history.
- [ ] Display unscored/pending/blocked states honestly; protect raw personal data.
- [ ] Refresh/navigation preserves case state; no UI-only decisions or synthetic live fallbacks.
- [ ] Trigger approved workflows through provider-independent application services and reconnect to persisted case/run IDs after browser closure; a separate always-running HTTP backend is optional, but deployed task execution is required.
- [ ] Show the DAG, parallel branches, numbered attempts, durations, sanitized errors and terminal outputs; distinguish execution success, source coverage and business assessment, and use durable workflow projections rather than unpublished legacy tables.
