## Acceptance Criteria

- [ ] Decide single-installation versus hosted multi-tenant support and document ownership of identities, service credentials, data residency and quotas.
- [ ] For approved hosted scope, create bounded child issues for membership invitation/revocation, case ownership, offboarding and tenant-bound secret/pool isolation.
- [ ] Never accept arbitrary customer cloud credentials through a public endpoint or store all customer secrets in one shared dotenv file.
- [ ] Verify tenant offboarding and installation removal retain/delete data according to approved policy; hosted billing/control-plane features stay deferred unless requested.

## Verification

Review hosting decision and child tasks; require revoked membership, tenant deletion, connection isolation and secret rotation tests for any supported hosted profile.

Record commands/results, decisions, deferred child issues and live versus fixture/replay boundaries.

## Guardrails

- No secrets, raw personal data, synthetic live fallbacks or source-rights bypasses.
- Cloud/account/schedule changes and paid access require explicit approval.
- Preserve provenance, pending/blocked coverage and trusted tenant/actor boundaries.
- No unsupported legal verdicts or scores from incomplete identity/evidence/coverage.
